# Proposal: Sandboxed panes

Зависит от: pane-profiles

Status (2026-11-17): **active** — no longer deferred (owner, session TILR-892). macOS uses
Seatbelt (`sandbox-exec` with a profile tilrd generates; design D10), decided by the owner on
2026-11-17 after the probe; Linux uses Landlock plus seccomp (design D5).

## Why

A pane in a sandbox for agents was proposed with open questions: Seatbelt per pane vs an App Sandbox signed pane binary on macOS (a quarantine experiment), Landlock or bubblewrap on Linux, per-pane loopback alias IPs (`127.10.x.x`), a tilrd-in-Docker mode, and a token that can only create sandboxed panes (Basic Memory `main/projects/tilr/tilr-ficha-sandboxed-pane-panel-v-pesochnitse-dlia-agentov`).

The prototype in `runtime-tmp` (`docs/how-it-works.md` §12) ran the App Sandbox helper bundle
per spec hash and found its limits: on the pty App Sandbox refuses `tcsetattr`,
`tcgetpgrp`/`tcsetpgrp` and `TIOCGETD` (`EPERM`), so no raw mode (vim, less, Claude Code do
not work) and no job control (shells forced to `+m`); files made inside get
`com.apple.quarantine` and cannot be executed inside; one container per spec hash, never
cleaned up. It has no Linux mechanism.

On 2026-11-17 the owner decided: the sandboxed pane is done now; it must behave as a normal Tilr
pane (raw mode, TUIs, job control); the request comes from the pane's launch profile
(`[sandbox]` in `profiles/<name>.toml`, change `pane-profiles`); macOS mechanism candidates, in
order: App Sandbox with an SBPL exception entitlement allowing the tty ioctls, a pty opened inside
the App Sandbox, Seatbelt; Linux: Landlock, unchanged. After the probe (macOS 26.6.2, arm64;
design D10) the owner decided the same day: Seatbelt, a deny-default profile generated by tilrd
from `[sandbox]`, run with `sandbox-exec`; App Sandbox rejected.

## Decision (2026-10-18)

Kept for the record; superseded items are marked.

- macOS: App Sandbox. The supervisor starts a separately signed pane binary that carries the sandbox entitlements (per the Basic Memory note: `com.apple.security.app-sandbox`, `network.client`, file exceptions for the allowed paths). **Superseded 2026-11-17**: App Sandbox is rejected (its profile refuses `file-ioctl` on the pty slave; the SBPL exception that fixes it brings quarantine, a signed helper per profile, containers); macOS uses Seatbelt (design D10).
- Linux: Landlock, applied in the pane's `pre_exec` before the shell, inherited by all the shell's children, no root: file rules need kernel ≥ 5.13, TCP bind/connect rules ≥ 6.7. **Stands.**
- First step is an experiment on `com.apple.quarantine`: scripts and `cargo`-built binaries created inside an App Sandbox pane must run. If they cannot, the macOS approach is reconsidered. **Answered by the prototype and the probe**: under App Sandbox they cannot; under Seatbelt they run (no `com.apple.quarantine`). Now a requirement.
- Rejected for now: Seatbelt `sandbox_init` profiles (deprecated API). **Superseded 2026-11-17**: Seatbelt is the macOS mechanism; the deprecation is an accepted risk (design D10).
- Rejected for now: a tilrd-in-Docker mode (stays an idea, out of scope). **Stands.**
- "Deferred / optional" status. **Lifted 2026-11-17.**
- `CreatePane` gains a sandbox request. **Superseded 2026-11-17**: the request is the profile's `[sandbox]`; `CreatePane` gets no sandbox fields.

## What Changes

- A pane created with a profile that has `[sandbox]` runs its program, and everything it
  starts, restricted to the profile's grants: files (`read_only`, `read_write`), programs
  (`executables`), network (`none` | `client` | `server`) and inherited variables (`env`).
- The pane works as a normal pane: raw mode, TUIs (vim, less, Claude Code), job control, `stty`;
  scripts and binaries made inside are executable inside.
- A sandboxed pane cannot reach the server or the user's agent: no tilr tools (`TILR_SHIMS`),
  no host-events or agent sockets, no server socket, no state directory (token).
- Mechanisms: Linux — Landlock plus a seccomp filter in the shell's `pre_exec`; macOS — Seatbelt:
  tilrd generates a deny-default profile from `[sandbox]` and starts the program through
  `/usr/bin/sandbox-exec` and a `tilrd sandbox-shell` trampoline. No helper app, no signing.
- Fail closed: if the restriction cannot be applied, the program is not started and
  `CreatePane` gets `Error` `create pane: sandbox: …`.
- `HelloAck.features` lists `sandbox` where this server can enforce (Linux with Landlock ABI ≥ 4;
  macOS: `/usr/bin/sandbox-exec` present and a test profile applies). Without it, `pane-profiles` already refuses sandboxed profiles.
- `PaneInfo.sandboxed` (field 13) is true for a sandboxed pane.
- The restriction survives a reload; per-pane artifacts (temporary directory, and on macOS what the
  mechanism makes) are removed when the pane ends and swept at start.
- Protocol: version 1 stays (policy in `openspec/config.yaml`); `PaneInfo.sandboxed` and the
  feature are additive. `sandbox` is a feature because a server can be run without it.

## Capabilities

### New Capabilities
- `pane-sandbox`: what a sandboxed pane may and may not do, how it behaves, fail-closed rules,
  reload, cleanup.

### Modified Capabilities
- `protocol`: "Server feature flags" (`sandbox`).

## Non-goals

- App Sandbox, VMs, Endpoint Security / Network Extension, a `DYLD_INSERT_LIBRARIES` interposer.
  **Changed 2026-11-17**: Seatbelt left this list (it is the macOS mechanism).
- tilrd in Docker.
- Network isolation beyond `none | client | server`; per-pane loopback aliases; domain
  allowlists.
- A token that can only create sandboxed panes (bus rights in `bus-acl-biscuit` / `bus-panes`
  cover Tilr's own use; a TCP token kind is `read-only-viewer`'s area).
- Sandboxing bus instances (a later change on top of `component-bus`).
- Sandboxing `ExecStart` or the files protocol (they act for the client, not for the pane).

## Impact

`crates/tilrd/src/{pty,supervisor,pane}.rs`, new `crates/tilrd/src/sandbox/` (Linux Landlock +
seccomp; macOS Seatbelt profile generation and the `sandbox-shell` trampoline), `crates/tilr-proto/proto/tilr.proto` (`PaneInfo.sandboxed`,
the `sandbox` feature comment), README ("Launch profiles", "Sandboxed panes", "Protocol"),
USE_CASES.md, `deny.toml` if a Landlock crate brings a new license. macOS: nothing to sign or bundle (Seatbelt needs no helper app); the release archive is unchanged.

Reload: the snapshot from `pane-profiles` already carries the sandbox; the restriction lives in
the kernel on the program's process tree (Linux) and is not affected by the pane process's
exec (macOS Seatbelt and Linux alike). No new state format beyond `pane-profiles`' format 3.

Not breaking: additive field and feature, no PROTOCOL_VERSION bump, no close code or CDN change.
