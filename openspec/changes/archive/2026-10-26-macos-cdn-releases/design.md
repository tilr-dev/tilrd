# Design

For manual releases, the release script dispatches macOS builds to a native macOS helper, mapping each platform to its Apple Cargo target. The helper builds both executables, signs them with Developer ID, hardened runtime and a timestamp, verifies their signatures, and submits a ZIP containing those exact binaries to notarytool. Only an Accepted response permits the normal flat CDN archive and checksum to be written. The helper copies accepted binaries into dist/<platform>, which also feeds GitHub packaging.

CI separates compilation, signing, and packaging onto fresh runners. Dependency build scripts execute only in the credential-free build job, which uploads unsigned binaries and SHA-256 checksums. The sign-macos job has no checkout or build commands: it verifies the download, imports a non-exportable Developer ID key and notary credentials from apple-signing, signs and requires Accepted notarization, and uploads signed binaries. Its temporary keychain is removed even on failure; signing metadata is not exported through GITHUB_ENV. Packaging consumes only signed macOS artifacts. This prevents dependency build scripts from using signing credentials or persisting a process until credentials appear. Both macOS platforms always participate in CDN publication; Linux arm64 remains controlled by its existing variable. Upload-only consumes the completed artifacts without Apple credentials or rebuilding.

Integration tests stub external build/sign/notary commands, inspect archived signed bytes and checksum validation, exercise failures before publication, and run the native updater against the layout the release script actually produces. Real Apple service acceptance is required in the release workflow.
